# План доработки PWA — Bonbon (Lottie Editor)

> Составлен по результатам анализа: в текущем виде PWA-составляющая отсутствует
> (нет манифеста, Service Worker, офлайн-работоспособности), несмотря на заявления
> «PWA-ready» в README.

---

## Текущее состояние (baseline)

| Аспект | Статус |
|---|---|
| Web App Manifest (`manifest.webmanifest`) | ❌ отсутствует |
| Service Worker (`sw.js`, регистрация) | ❌ отсутствует |
| Офлайн-работа | ❌ невозможна: `lottie.min.js` грузится с CDN (`index.html`, строка 7) |
| `<meta name="theme-color">`, иконки для установки | ❌ отсутствуют |
| Сохранение проекта между сессиями | ❌ только ручное скачивание JSON |
| Адаптивная раскладка (мобильные) | ❌ фиксированная сетка `220px / 1fr / 260px`, `height:100vh` |
| Архитектура (один HTML, Vanilla WC, без сборки) | ✅ хорошая предпосылка для PWA |

**Цель:** довести приложение до настоящего устанавливаемого PWA с гарантированной
офлайн-работой, привести README в соответствие реальности.

## Этап 1 — Убрать зависимость от CDN (критический блоккер офлайна) (0.5–1 день)

- [ ] Скачать `bodymovin/5.12.2/lottie.min.js` и забандлить в проект:
      - **вариант A (сохраняем «единый файл»):** инлайн `<script>` прямо в `index.html`;
      - **вариант B (чище):** локальный `vendor/lottie.min.js` + `<script src="./vendor/lottie.min.js">`.
- [ ] Добавить graceful degradation: если `window.lottie` не определён — показать
      понятную ошибку вместо тихого краха.
- [ ] Проверить отсутствие других внешних запросов (шрифты, favicon, аналитика) — по
      итогам анализа их нет, зафиксировать это тестом.
- **Критерий приёмки:** приложение полностью функционально при отключенной сети
  (DevTools → Network → Offline) сразу после первого визита.

## Этап 2 — Манифест и метаданные установки (0.5 дня)

- [ ] Создать `manifest.webmanifest`:
  ```json
  {
    "name": "Bonbon — Lottie Editor",
    "short_name": "Bonbon",
    "start_url": "./",
    "scope": "./",
    "display": "standalone",
    "orientation": "landscape",
    "background_color": "#1e1e1e",
    "theme_color": "#1e1e1e",
    "icons": [
      { "src": "icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
      { "src": "icons/icon-512.png", "sizes": "512x512", "type": "image/png" },
      { "src": "icons/icon-maskable-512.png", "sizes": "512x512", "type": "image/png",
        "purpose": "maskable" }
    ]
  }
  ```
- [ ] Нарисовать/сгенерировать иконки (192, 512, maskable) в фирменном стиле (`--accent`).
- [ ] В `index.html` добавить:
  - `<link rel="manifest" href="./manifest.webmanifest">`
  - `<meta name="theme-color" content="#1e1e1e">`
  - `<link rel="apple-touch-icon" href="icons/icon-192.png">`
  - `<meta name="mobile-web-app-capable" content="yes">` (+ legacy `apple-mobile-web-app-capable`)
- [ ] Обработать `beforeinstallprompt`: кнопка «Установить» в тулбаре (или баннер).
- **Критерий приёмки:** Chrome DevTools → Application → Manifest без ошибок;
  Lighthouse PWA-проверка манифеста зелёная; установка на рабочий стол/домашний экран работает.

## Этап 3 — Service Worker: офлайн-кэш оболочки (1 день)

- [ ] Создать `sw.js`:
  - `install`: precache `[ './', './index.html', './vendor/lottie.min.js', './manifest.webmanifest', './icons/*' ]`, `skipWaiting()`;
  - `activate`: cleanup старых версий кэша, `clients.claim()`;
  - `fetch`: **app-shell, cache-first** для навигации и статики того же origin;
    сеть-с-фолбэком-в-кэш на будущее для внешних ресурсов.
- [ ] Версионировать имя кэша (`bonbon-v1`) — способ инвалидации при релизах.
- [ ] Регистрация в `index.html`:
  ```js
  if ('serviceWorker' in navigator) {
    addEventListener('load', () => navigator.serviceWorker.register('./sw.js'));
  }
  ```
- [ ] Показать в UI индикатор статуса: «офлайн-режим активен / кэш устарел / доступно обновление»
  (событие `updatefound` + кнопка «Перезагрузить»).
- **Критерий приёмки:** выключить сеть → перезагрузка → приложение открывается и редактирует;
  второй визит без сети не требует повторной загрузки страницы.

## Этап 4 — Персистентность данных пользователя (1–1.5 дня)

- [ ] Автосохранение текущего проекта (состояние модели + история) в `localStorage`
      с дебаунсом ~1 с; при старте — восстановление с подтверждением («Продолжить прошлый проект?»).
- [ ] Лимиты: размер lottie-JSON может быть большим → при превышении квоты (обычно ~5 МБ)
      мигрировать на IndexedDB (без библиотек, ~50 строк) либо ограничить число автосейвов.
- [ ] Библиотека проектов: список сохранённых композиций (IndexedDB: `id, name, updatedAt, json`),
      UI-панель «Мои проекты», переименование/удаление.
- [ ] Экспорт/import состояния приложения (zip/json) — бонусом для бэкапа.
- **Критерий приёмки:** закрытие вкладки/перезапуск установленного приложения не теряет работу.

## Этап 5 — Файловая система и интеграция с ОС (1 день, из Roadmap)

- [ ] File System Access API: «Открыть…» / «Сохранить как…» с handle, хранящимся в IndexedDB
      (для повторного сохранения без диалога); фолбэк — текущий Blob-download.
- [ ] Drag&drop `.json` в окно + обработка `file://`-ассоциации через manifest
      (`file_handlers` — Chromium).
- [ ] Web Share Target (по желанию): шаринг `.json` в приложение с мобильных.
- **Критерий приёмки:** типичный пользовательский путь «из редактора ↔ файл на диске» ≤ 2 действий.

## Этап 6 — Адаптивность под мобильный/установленный запуск (1.5–2 дня)

- [ ] Breakpoints: при ширине < ~900px панели `layers`/`props` превращаются в
      выдвижные tab-оверлеи поверх canvas (bottom tab bar: Слои / Холст / Свойства).
- [ ] Тач-цели ≥ 44px: увеличить hit-area слайдеров, кнопок таймлайна, чанков свойств.
- [ ] Поддержка pinch-zoom панорамирования превью (pointer events уже есть — расширить).
- [ ] `orientation: landscape` в манифесте + корректная работа в portrait.
- [ ] Safe-area insets (`env(safe-area-inset-*)`) для standalone-окна с вырезом.
- **Критерий приёмки:** на телефоне (390×844) можно открыть, отредактировать и экспортировать
  анимацию без горизонтального скролла и «мелкого шрифта».

## Приоритеты и порядок

```
Этап 1 (CDN) ──► Этап 3 (SW) ──► Этап 2 (манифест)   ← ядро «настоящего PWA»
                     │
                     ├──► Этап 4 (данные)  ← главная ценность офлайна для пользователя
                     ├──► Этап 5 (FS API)  ← из исходного Roadmap
                     └──► Этап 6 (мобилки) ← можно параллельно/последним
Этап 0 (README+ветка) — до всего остального
Этап 7 — после всего
```

Блокеры: без Этапа 1 любой SW-офлайн бессмысленен (приложение не стартует без CDN-скрипта).

## Риски

- **Единый HTML-файл vs отдельные sw.js/manifest** — SW нельзя инлайнить; придётся
  пожертвовать идеей «один файл» (или инлайнить всё, кроме двух обязательных файлов).
- **Квота localStorage** на больших композициях → IndexedDB (Этап 4 учтён).
- **CSP + инлайн-стили/скрипты** в нынешнем коде их активно используют → либо nonce,
  либо вынос кода во внешние файлы (доп. рефакторинг).
- **File System Access API** — только Chromium; нужен фолбэк (учтено).
- Кэширование CDN-версии lottie вместо локальной — хрупко (CORS/версии); предпочтителен Этап 1.

## Definition of Done для «PWA-ready»

1. Lighthouse: PWA-секция без ошибок; установка possible desktop + Android.
2. Полный цикл редактирования при `navigator.onLine === false` после первого визита.
3. Проект восстанавливается после перезапуска приложения (автосейв).
4. README описывает только реализованное; roadmap-пункты PWA закрыты.
